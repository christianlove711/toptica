# DLC pro 电流控制 Demo 完整开发过程

## 1. 目标

本次 Demo 的目标不是做一个完整实验室软件，而是做一个可运行、可讲解、可继续扩展的最小版本：

- 连接 DLC pro
- 读取设备基础信息
- 读取电流设定值与实际值
- 连续更新电流设定值
- 使用中文、现代化 GUI

## 2. 设计原则

### 2.1 严格依赖官方 SDK 源码

本 Demo 没有自己猜测新的高层对象名，而是严格基于以下官方安装源码：

`toptica.lasersdk.dlcpro.v2_6_0`

确认使用的接口包括：

- `DLCpro`
- `NetworkConnection`
- `dlc.system_type`
- `dlc.serial_number`
- `dlc.system_label`
- `dlc.uptime_txt`
- `dlc.laser1.dl.cc.enabled`
- `dlc.laser1.dl.cc.emission`
- `dlc.laser1.dl.cc.current_set`
- `dlc.laser1.dl.cc.current_act`

### 2.2 Demo 与主项目隔离

为了不把当前主项目越改越乱，本次单独创建了：

`demo_dlcpro_current/`

这样做的好处：

- 便于快速验证想法
- 便于给老师展示
- 后续可以决定是否合并回主 GUI

### 2.3 电流控制交互采用连续更新

用户明确要求不要做“先输入再确认”的传统实验参数框，而更像旋钮那种实时调节。

因此这里选择：

- `QSlider`
- `QDoubleSpinBox`
- 短时间防抖写入

这样既接近连续调节，也避免滑杆拖动时每一个像素变化都立刻狂写设备。

## 4. 分层说明

### 4.1 controller.py

职责：

- 管理 DLC pro 连接
- 读取状态
- 写入电流设定值

关键类：

- `DemoConnectionSettings`
- `DemoDeviceStatus`
- `DlcproCurrentDemoController`

为什么单独抽控制器：

- GUI 不直接碰 SDK
- 更容易测试
- 后面可以单独复用到别的界面

### 4.2 window.py

职责：

- 创建中文 GUI
- 响应按钮、滑杆、数值框
- 定时刷新显示
- 把用户交互转成控制器调用

### 4.3 app.py

职责：

- 启动 PySide6 应用

## 5. 官方接口是怎么用到的

真实设备连接时，核心读取逻辑是：

```python
with DLCpro(connection) as dlc:
    dlc.system_type.get()
    dlc.serial_number.get()
    dlc.system_label.get()
    dlc.uptime_txt.get()
    dlc.laser1.dl.cc.enabled.get()
    dlc.laser1.dl.cc.emission.get()
    dlc.laser1.dl.cc.current_set.get()
    dlc.laser1.dl.cc.current_act.get()
```

写入电流设定值时：

```python
dlc.laser1.dl.cc.current_set.set(float(value_ma))
```

这部分完全基于 `v2_6_0.py` 已确认的高层接口。

## 6. 为什么还保留 Demo 模式

即使老师现场没有把设备接好，也需要能演示界面结构与交互方式，因此保留了 `Demo 模式`。

Demo 模式的作用：

- 无硬件时先调界面
- 给老师展示交互
- 检查滑杆和连续更新逻辑

## 7. GUI 设计思路

### 7.1 中文化

为了方便实验室内部直接使用：

- 所有按钮、标签、说明文字都是中文
- 代码注释也是中文

### 7.2 现代化外观

界面采用了：

- 顶部渐变标题区
- 白色卡片式面板
- 较大的电流数值卡片
- 清晰的蓝色强调色

目标不是做工业软件最终版，而是做一个能快速沟通设计方向的演示版。

### 7.3 连续更新电流

用户要求电流控制更像旋钮，因此这里的流程是：

1. 拖动滑杆
2. 同步更新数值框
3. 启动一个短防抖定时器
4. 定时器到时后自动写入 DLC pro

这样比“点确认”更自然，也比每毫秒直接写入设备更稳。

## 8. 为什么没有继续往下做更激进的控制

当前 Demo 只做到电流读写，是因为：

- 电流设定值在源码里已经明确确认
- 功能闭环最简单
- 最适合做第一步真机验证

没有先做的内容包括：

- 出光开关联动
- 锁定控制
- 扫描流程控制
- Recorder 下载与绘图

这些都需要更多安全约束和实验流程确认。

## 9. 依赖处理

本次把这些依赖显式写入项目：

- `PySide6`
- `toptica-lasersdk`
- `ifaddr`
- `pyserial`

其中：

- `ifaddr` 常见于 TOOPTICA SDK 网络发现相关依赖
- `pyserial` 保障串口路径的环境完整性

## 11. 当前 Demo 的价值

这个 Demo 已经能回答几个关键问题：

- 官方 SDK 高层接口能不能直接用于实验室自研软件：可以
- 不依赖官方 GUI，能不能自己做中文界面：可以
- 能不能做到接近旋钮式的连续电流调节：可以
- 开发是不是瞎编参数：不是，本 Demo 直接基于 `dlcpro.v2_6_0` 源码确认接口
